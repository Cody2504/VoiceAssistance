# Agent tool-call trajectory eval

Benchmarks the agent's retrieval **routing + argument correctness** (deterministic),
plus **TaskCompletion** and **AnswerRelevancy** (`gpt-4.1` LLM-judge). Design:
`docs/superpowers/specs/2026-06-19-agent-tool-trajectory-eval-design.md`.

## Run

```bash
cd backend/agent-service
export PYTHONPATH="$(cd ../.. && pwd)/backend:$(pwd):$(pwd)/main"

# `--env-file` loads the agent's LLM settings (router gpt-4o / reflect gpt-4o-mini)
# AND the judge's OPENAI_API_KEY. Only non-empty values are applied.

# Routing + args only (no judge API calls — but ToolCorrectness still needs a key present):
.venv/bin/python -m agent_eval.run_eval --env-file ../.env --no-judge --out eval_report.md

# Full eval incl. judged metrics. Router is overridden to gpt-4.1 (cheaper than the
# .env's gpt-4o); judge is gpt-4.1-mini (set in metrics.py). The exported var wins
# because --env-file applies .env values with setdefault.
OPENAI_PLANNER_MODEL=gpt-4.1 .venv/bin/python -m agent_eval.run_eval --env-file ../.env --out eval_report.md

# Filter to specific tools / smoke a single case:
.venv/bin/python -m agent_eval.run_eval --env-file ../.env --no-judge --tools ground_video --limit 1

# Via OpenRouter (uses OPENROUTER_API_KEY from --env-file; router=openai/gpt-4.1,
# reflect=openai/gpt-4o-mini, judge=openai/gpt-4.1-mini):
.venv/bin/python -m agent_eval.run_eval --env-file ../.env --openrouter --out eval_report.md

# Against the real video-service instead of fakes (needs live backend + real ids):
.venv/bin/python -m agent_eval.run_eval --env-file ../.env --live
```

## OpenRouter
`--openrouter` points both LangChain (the agent's router/reflect) and deepeval (the judge)
at OpenRouter — it's OpenAI-compatible, so no agent code changes are needed (LangChain reads
`OPENAI_API_BASE`, the openai SDK reads `OPENAI_BASE_URL`; both are set from
`OPENROUTER_API_KEY`). Override any model with `OPENAI_PLANNER_MODEL` / `OPENAI_WORKER_MODEL`
(router/reflect) or `EVAL_JUDGE_MODEL` (judge) — use OpenRouter ids like `openai/gpt-4.1` or
`google/gemini-2.0-flash`.

**Cost:** OpenRouter is **not cheaper for the same models** — it passes provider pricing
through at cost and adds a ~5% credit-purchase fee, so `openai/gpt-4.1-mini` via OpenRouter
≈ OpenAI's price. Its value here is (a) spending existing OpenRouter credit, and (b) access
to genuinely cheaper non-OpenAI models (e.g. Gemini Flash, DeepSeek) if you swap the model ids.

CI gate (opt-in): `RUN_AGENT_EVAL=1 [EVAL_JUDGE=1] .venv/bin/python -m pytest tests/agent_eval/test_agent_eval.py`.

## Modes
- **Fake (default):** real LangGraph + real LLM router, tools stubbed from each golden's
  `fake_outputs`. Deterministic, network-free, reproducible.
- **Live (`--live`):** same goldens against the real backend.

## What a green fake-mode score means
The agent **reasoned correctly given correct retrieval** — not that retrieval was correct.
Clip-level retrieval quality (Recall@K / mAP / IoU) is the deferred Layer-2 (see spec §2/§11).

## Models & cost
- **Router** (genuine routing decision): `gpt-4.1` — override `OPENAI_PLANNER_MODEL` at run
  time (see the command above) so the eval doesn't use the `.env`'s pricier `gpt-4o`.
- **Reflect** (final answer): `gpt-4o-mini` (from `.env`).
- **Judge** (TaskCompletion / AnswerRelevancy): `gpt-4.1-mini` — `JUDGE_MODEL` in `metrics.py`.

We started the judge on `gpt-5`, but its reasoning latency on deepeval's structured-output
verdicts exceeded deepeval's default 30s per-attempt timeout
(`DEEPEVAL_PER_ATTEMPT_TIMEOUT_SECONDS`); `gpt-4.1-mini` is fast, cheap, and well within it.

**Bias caveat:** the judge and the agent's router/reflect are all OpenAI models, so
same-family judging can carry mild self-preference bias on the **judged** metrics. The
deterministic metrics (ToolCorrectness, argument correctness) are unaffected. To remove
the bias, point `JUDGE_MODEL` at a non-OpenAI model.

## deepeval 4.x note
`ToolCorrectnessMetric` is deterministic (local tool-name matching, no network call) but
its constructor requires `OPENAI_API_KEY` to be *present*. The offline unit tests set a
placeholder key in `tests/agent_eval/conftest.py` (`setdefault`, so a real key is left
untouched). `--no-judge` runs therefore still need *some* `OPENAI_API_KEY` value in the
env, but make no judge API calls.

## Extending the dataset
The dataset is generated by `agent_eval/build_goldens.py` (one source of truth) into
`agent_eval/goldens/*.yaml` — currently **107 cases across 17 tools**. Edit the per-tool
query lists in `build_goldens.py` and re-run `python -m agent_eval.build_goldens` to extend
coverage, or hand-edit the YAML directly (the loader globs all `*.yaml`).
